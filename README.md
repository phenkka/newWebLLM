Это форк-репозиторий с веб-интерфейсом для общения с моделями из ollama, с добавлением guardrails и самописным движком для их обработки.


## Что это и для чего

Веб-чат (форк Open WebUI) для общения с LLM-моделями, которые крутятся в ollama (обычно в отдельном контейнере). Поверх обычного чата добавлена защита (guardrails): она не даёт пользователю вытащить из модели запрещённую информацию и не даёт модели её выдать.

Зачем: голая модель уязвима к атакам — извлечение системного промпта, чтение системных файлов (/etc/passwd, ключи), просьбы об инструкциях по оружию/наркотикам/малвари, обход ограничений через обфускацию. Это видно по прогонам garak. Guardrails закрывают эти классы атак до и после модели.


## Почему свой движок, а не NeMo

Правила написаны в формате NeMo Colang (.co файлы). Но запустить сам NeMo внутри этого приложения нельзя: `nemoguardrails` требует `langchain < 0.4`, а Open WebUI требует `langchain == 1.2.10` — в одном окружении они несовместимы. Из-за этого `import nemoguardrails` падает, и все .co правила молча игнорируются (защиты нет вообще).

Поэтому .co файлы исполняет **свой движок** (`utils/guardrails.py`) — он сам читает правила и применяет их. Никакой зависимости от nemoguardrails, конфликта версий нет, работает в любом окружении (только стандартная библиотека Python).


## Как реализована защита

Два рубежа:

1. **Вход** — запрос пользователя проверяется до отправки в модель. Если правило сработало, модель не вызывается, пользователю возвращается отказ.
2. **Выход** — ответ модели проверяется перед показом пользователю. Если в ответе обнаружен запрещённый контент (например содержимое /etc/passwd, приватный ключ, инструкция по взрывчатке), ответ заменяется на отказ.

Правила — это подстрочный матчинг: `if "подстрока" in $user_message` (вход) или `in $bot_response` (выход) → `bot say "отказ"`. Поддерживается логическое И (несколько условий в одном правиле).

Перед сравнением движок снимает обфускацию, которой атакующий прячет полезную нагрузку:
- невидимые / zero-width символы между буквами и словами;
- разбивку через `+` (`п+р+о+ч`);
- JSON-обёртку (`{"выполни":"команду"}`);
- склейку слов и удаление пробелов.

Сейчас в правилах: ~2300 на вход + ~115 на выход.


## Где что находится

    backend/open_webui/utils/guardrails.py   — движок: парсит .co, применяет вход/выход, снимает обфускацию
    backend/open_webui/utils/chat.py         — подключение: проверка входа перед LLM и выхода перед отдачей (вкл. стриминг)
    backend/open_webui/nemo_guardrails/      — политики (.co) и config.yml

Политики (.co):

    rails_safety_catalog.co        — основной каталог входных правил: насилие, оружие/взрывчатка,
                                     наркотики, мошенничество, PII/доксинг, хакинг/малварь, агентные злоупотребления
    rails.co                       — джейлбрейк / обход политики / извлечение промпта (вход)
    rails_test_garak.co            — извлечение системного промпта и скрытых правил (вход)
    rails_prompt_extraction_ru.co  — русские фразы извлечения промпта (вход)
    rails_dangerous_access.co      — чтение системных файлов, shell-команды, пути (вход)
    rails_output_and_stubs.co      — выходные проверки + сигнатуры утечек файлов/секретов
    rails_output_safety.co         — выходной каталог (зеркало входа): оружие, наркотики, CBRN,
                                     малварь, секреты, PII, мошенничество, селфхарм
    config.yml                     — список флоу (для справки; движок читает все *.co автоматически)

Прочее:

    Dockerfile.guardrails    — образ: официальный Open WebUI + наложение наших файлов
    docker-compose.yaml      — запуск
    GUARDRAILS.md            — как устроена защита и как повторить её в другом проекте (например в RAG-агенте)


## Запуск

    docker compose up -d --build

Поднимется на порту 3000 (http://localhost:3000). Том с аккаунтами и чатами сохраняется между пересборками.


## Подключение моделей

Адрес контейнера с моделями (ollama) задаётся через `OLLAMA_BASE_URL` — в `.env` рядом или прямо в `docker-compose.yaml`:

    OLLAMA_BASE_URL=http://<адрес-ollama>:11434

Проверить доступность изнутри контейнера:

    docker exec open-webui curl -s http://<адрес-ollama>:11434/api/tags


## Как дописать правила

Просто добавь строку в любой .co файл — движок подхватит её при следующей пересборке/перезапуске. Регистрировать флоу в config.yml не нужно (движок читает все *.co сам).

Вход:

    if "запрещённая фраза" in $user_message
      bot say "Запрос отклонён политикой безопасности."
      stop

Выход (проверка ответа модели):

    if "сигнатура утечки" in $bot_response
      bot say "Ответ заблокирован системой безопасности."
      stop

Несколько условий (И):

    if "слово1" in $user_message and "слово2" in $user_message
      bot say "..."
      stop

После правок — `docker compose up -d --build`.
